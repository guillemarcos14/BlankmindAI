# Production app activation

The production iOS app uses Sign in with Apple and an in-app Blankmind conversation. Phone OTP and WhatsApp remain on the external Early Access site, whose OTP uses `waitlist-auth`; production iOS uses only `app-auth` for Apple ID-token sign-in and session refresh.

1. First launch opens a two-step `SetupView`: the person signs in with Apple, then prepares this iPhone. The Apple request asks for no email/name scopes and sends a nonce to Supabase. A legacy authenticated phone session is linked to Apple so its Supabase user ID and conversation history remain the same. New accounts receive an identity row with nullable `phone_e164`.
2. The app calls `assistant-app?action=activate` with its Supabase JWT and `app_install_id`. The server creates/reuses `blankmind_identity_links`, binds this installation and returns its internal connect code. Conversation turns and the app channel are keyed by the authenticated Supabase user ID, never a phone number.
3. Device setup requests Screen Time authorization, a nonempty canonical distraction selection and notification permission. It registers the real APNs token and syncs context through `assistant-channel`; these app routes require the same JWT, matching identity and installation.
4. On completion, onboarding opens Home. Home includes the Chat section plus a text/dictation composer; sending the first message opens the in-app conversation. There is no WhatsApp route or phone-number prompt in the production app.
5. Blocking requests retain the durable pending-action and native confirmation lifecycle. The app reports verified execution only after the device receipt.

Supabase production `blank-membership` has Apple enabled for `com.blanknfc.web,com.blanknfc.app.ios` and manual identity linking enabled. Private staging has Apple enabled for `com.blanknfc.app.ios`, no OAuth secret, and manual linking enabled (dashboard verified after reload 2026-09-27). Apple Developer confirms Sign in with Apple on the primary app identifier; four existing app/extension development and App Store profiles were regenerated and verified valid. Before release, install profiles on the build Mac and prove a signed build plus new/legacy Apple sign-in on iPhone. No Supabase migration is added; production still requires the existing identity and conversation migrations. The simulator/build harness does not prove APNs delivery, signing or physical Screen Time execution.
