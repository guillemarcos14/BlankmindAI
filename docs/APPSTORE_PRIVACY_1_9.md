# App Store privacy reconciliation, version1.9

Current public policy: https://blankmind.ai/privacy (Sites103,13October2026). The native account consent names OpenAI and ElevenLabs and requires a renewed v2 choice; refusal/withdrawal preserves basic blocking. Adding a provider does not by itself introduce a new Apple data category, but the completed spoken text can contain health/personal context.

Match App Store Connect to the actual enabled release, including retained legacy services. The old1.7 checklist excludes health and user content and must not be reused. The1.8 checklist incorrectly treats user ID as contact information and its blanket Analytics purpose must not be applied to health data.

| Actual flow | Apple category | Purpose / linkage |
| --- | --- | --- |
| Apple-provided email/private relay stored by Supabase Auth; support email when supplied | Contact Info: Email Address | App Functionality; linked to account |
| Authentication user ID, install ID, voice turn/quota identifiers | Identifiers: User ID / Device ID as appropriate to each identifier | App Functionality; product-event Analytics only for the event identifier; linked to account/install |
| Messages to Blankmind, replies, onboarding answers and facts deliberately shared | User Content: Other User Content; Name if collected in onboarding | App Functionality / Product Personalization; linked to account |

| Permission/readiness status, selection counts, block/unlock outcomes and product funnel events | Usage Data: Product Interaction; Other Data Types for unmatched operational fields | App Functionality and actual product-event Analytics; linked to account/install |
| Legacy StoreKit entitlement when transmitted/stored by developer backend | Purchases: Purchase History | App Functionality; linked to account; no card data |

Exact selected apps/websites, broad local Progress/clinical data, passwords, contacts, browsing history, IDFA and payment card details are not transmitted by these implemented app flows. Generated ElevenLabs output is synthetic speech; this route does not upload a microphone recording or persist an audio recording. Do not mark Audio Data solely because text is played aloud. The app microphone is a separate, implemented upload: an m4a recording is sent through the authenticated backend to OpenAI transcription, and the transcript becomes user content. Review Audio Data against Apple collection definitions and actual provider retention; do not describe this as Apple speech recognition or infer no collection merely because this backend does not persist the recording. Apple keyboard dictation is distinct from the app microphone. Any future crash SDK needs its own declaration before activation.

Tracking remains No for the reviewed app flows; no third-party advertising SDK/IDFA is introduced. Do not claim anonymous/non-linked merely because an identifier is generated by the app: it persists and can connect to an authenticated account. No verified new App Store Connect privacy-label write is recorded in this task; review the existing ten declared types against the table and only change fields where their actual flow differs.
