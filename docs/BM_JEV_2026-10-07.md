# Jev advisory integration — 2026-10-07

Implementation based on optimized latency source `6d02cbb` (PR22). Flags default
off. No production deploy, TestFlight distribution, physical iPhone evidence or
approved activation is implied by this implementation.

## Authority and privacy

One pinned `jev-1.13.0` request batches six independent topic labels, one turn
intent, six source relevance questions and uncertainty. It never writes personal
facts, authorizes actions or replaces the generative planner. The planner's
permissions, explicit evidence, proposal fingerprint, CAS, lease, UUID, streaming,
durable response, memory commit, tombstones and recovery remain authoritative.

Initial scope is **synthetic private QA only**. Both server config and SQL require
the reserved QA database, an allowlisted UUID and server-side
`auth.users.raw_app_meta_data.synthetic_staging_run`. No real-user conversations
or health records are approved for this provider. State consists of the immutable
current turn and at most one recent completed conversational pair, after the
memory cutoff. No account identifiers, personal source records or device state
are sent to Jev. Retention/consent review is required before expanding that scope.
The key is a server secret, never in iOS, Git, reports or logs.

## Durable shadow and bounded experiment

Migration `029_bm_jev_advisory.sql` stores only advisory metadata with model,
taxonomy, provenance, probabilities, selected labels, usage and timing. The
existing scheduled BMB background worker scans eligible completed durable turns.
No promise is detached from a request; interrupted work is recovered from those
turns, including a crash before dispatch. SQL reserves a lease and daily fleet
budget before a vendor call. At most two attempts per UUID/taxonomy, five minute
backoff, 1000 requests / $1 conservative reservation per UTC day. Timeout failures
keep the reservation because the billed amount can be unknown. Account deletion
cascades; tombstones purge labels and invalidate in-flight completion. Aggregated
conversation labels are service-role-only and exclude forgotten history.

The experimental classifier runs concurrently with current memory/policy/followup
preparation, with a 600 ms total signal and 1800 ms shadow provider timeout. Up to
three source reads each have a 150 ms signal and use the existing closed catalog,
verified identity, data consent and memory cutoff. No automatic history retrieval
across forgetting, no source omission, no dropped essential context. Additional
planner reads and pagination remain available. Errors, uncertainty, lease loss,
absence or disabled config retain the current route. All dependencies are awaited.
Classification metadata never enters the planner's action or memory authority.

The experiment is restricted to synthetic QA and does not activate the critical
user route. `bm-jev-activation.json` stays disabled pending calibrated evaluation,
quality/cost/latency gates and the applicable consent/release process.

## Server configuration and rollback

`TYPESAFE_API_KEY` is the only secret added to Netlify, functions scope on the
reserved private QA site. Enabling a synthetic pilot requires all of:
`BM_JEV_SHADOW_ENABLED=true`, `BM_JEV_DATA_POLICY=synthetic-private-qa`,
`BM_JEV_QA_USERS=<verified synthetic UUIDs>`, `BM_JEV_QA_SINCE=<ISO start within
seven days>`, `BM_JEV_QA_PERCENT=1|5|25|100`. Only the local paired experiment
sets `BM_JEV_PREFETCH_EXPERIMENT=true`. Change one cohort percentage at a time;
check errors, unknown spend, accepted labels and reviewed examples before growth.
Disable shadow/experiment flags or set percentage zero to revert. Existing
turns/actions remain durable; additive tables may remain in place. No billing
subscription or automatic top-up was requested.

The packaged QA worker preserves the existing schedule/dispatch mechanism.
Enabling a cloud pilot requires checking that `bmb-tick` has the existing five
minute schedule in the integration deployment; packaging alone does not prove
scheduled execution. The local benchmark does not certify that transport.

## Corpus and evaluation

`tools/datasets/bm_jev_v1.json`: 300 authored synthetic examples, 150 ES / 150 EN;
100 adjustment / 200 reserved evaluation. Bilingual pairs stay together. Includes
sleep, rest, habits, distractions, support, other, multiple topics, ellipsis,
contextual acceptance, corrections, missing data, quotes, hypothetical/third-party
statements, injection and forgetting. Annotation was authored/reviewed by one
Codex agent, **not independently human reviewed**. Near-template overlap and small
per-label/per-language subsets limit external validity. Pending review is explicit.
`bm_jev_annotation_review.js` adds a second-model blind annotation check: expected
labels are omitted from its request and disagreements remain in the evidence.
This is model review, not human validation. Original annotations are not rewritten
after examining provider outputs.

`bm_jev_eval.js` compares a simple lexical baseline, calibrates only adjustment
records and computes heldout precision/recall per label, macro-F1, accepted-label
precision, accepted-turn coverage, intent and source scores by language. Targets
are >=95% accepted-label precision and >=80% turn coverage in both languages;
confidence is a concentration statistic, never a guarantee of accuracy.

Initial/revised request results and errors remain separate; modifying the prompt
must not be presented as unchanged evaluation. Reuse of adjustment output requires
matching request hashes and a reference hash. No heldout thresholds are selected.
The initial request also evaluated these heldout examples. The revised request
was changed using adjustment examples, but reuses that exposed holdout; it is not
a fresh independent validation set. Human annotation review and a new sealed
validation set are required before any activation claim.
The original generative planner already includes message_kind in its reply call;
there is no separate classification call to remove. `bm_jev_planner_compare.js`
compares the five shared intent labels on the same authored synthetic inputs,
using the original first reply schema/instructions and empty sources. It does not
run a complete planner workflow or validate actions. Topics and the remaining
intent categories have no equivalent planner enum and are excluded from that
comparison. First-read source queries are retained as diagnostics, not equivalent
topic labels. The paired runner has no final message_kind diagnostic.

## Paired workflow measurement

`bm_jev_benchmark.js --run --pairs 300 --baseline ../Codigo-latency
--candidate . --rates tools/datasets/bm_jev_rates_2026-10-07.json` runs 300 turns per
variant in alternating AB/BA order, with independently reset identical synthetic
fixtures. Real Jev + generative provider and private QA database; exact local
handlers. Includes missing sources, quotes, forgetting, complete/incomplete actions
and personal retrieval. The workflow is twelve scenarios repeated 25 times per
variant, with two Spanish and ten English templates; it is not 300 distinct
workflows or a representative population sample. Contextual acceptance is covered
by the classifier corpus and existing authority tests, not by this paired fixture.
Reports every failed turn and cleanup result, first text
and durable result p50/p95, DB/model calls, input/output/cached tokens and full
estimated generative + Jev cost. Per-request usage records must cover every model
call, including repairs/recovery; aggregate turn telemetry alone cannot certify
complete billing. Legacy runs without those counters retain a known lower bound
and an unknown upper bound. Unknown timeout billing is reported as an interval;
a cost gate cannot pass without a defensible upper bound. Synthetic
transcripts are retained separately for semantic review and are never console logs.

Compare against the optimized variant, which already contains the prior latency
changes (previous 100+100 reference: first text 3330->2700 ms, result 4136->3581 ms,
errors 11->2, DB queries 23->15). New targets: first-text median <=80% of optimized,
total mean cost <=80%, no worse first-text/result p95, quality or action authority.
Zero or one good sample is insufficient. Passing functional checks does not prove
semantic equivalence or physical execution. Failed gates keep activation off.

## Twenty physical iPhone cases

Use an integrated signed QA build with source/backend hashes recorded. Run four
repetitions of each class (20 total): advice, recorded sleep retrieval, missing
data, complete block/receipt, contextual acceptance then forgetting. Alternate
baseline/candidate order on the same network/device; record send, first visible
text, durable completion, replay, native receipt, permissions, quality and all
provider cost. Include foreground/background recovery and missing Health permission
among repetitions. Capture artifact SHA, iOS/build/device/network, turn UUIDs and
timestamps without real message content in logs. Never substitute Simulator,
local handler timing, a synthetic acknowledgement or APNs acceptance for iPhone
evidence. No physical runs have been performed by this task.
